# 面试复盘助手 需求文档（定稿版）

## 1. 产品概述
用户上传简历（PDF/Word）与面试对话文档（Word），系统用大模型理解并整理为问答对 markdown，切分后结合简历逐题分析，最终输出一份 markdown 复盘报告。

## 2. 用户流程
上传简历（pdf/docx）+ 对话（docx）→ 文本提取（简历做结构化摘要）→ 整理生成 `interview_qa.md` → 切分问答对 → 批量逐题分析 → 生成 `interview_review.md`。

## 3. 功能需求

### FR1 文件上传与文本提取
- **格式**：简历 `.pdf`/`.docx`；对话 `.docx`。
- **PDF 解析**：`pdfplumber`/`PyMuPDF` 逐页提取文本与表格；文本过短（<200 字）或几乎无字 → 判定疑似扫描件，提示"请上传可复制文本版本或启用 OCR"；多栏乱序做行合并校验，严重时提示。
- **Word 解析**：`python-docx` 遍历段落与表格，保留标题/列表结构；对话文档保留说话人前缀。
- **统一出口**：均归一为纯文本，简历文本进入 FR2；解析失败/空文本/图片型 → 明确报错，不静默继续。
- **不脱敏**（按用户要求），界面提示用户自行注意隐私。

### FR2 简历结构化摘要
- 简历文本交模型输出 JSON：`{基本信息, 教育, 工作经历[], 项目[], 技能[], 量化成果[], 亮点[]}`。
- 作为全局上下文供逐题分析引用；JSON 解析失败降级为纯文本摘要；失败重试。

### FR3 对话整理（生成 interview_qa.md）
- 识别角色，按序提取问答；剔除自我介绍与反问环节；最小必要清洗口语词（保留事实、术语、数据）。
- **追问处理**：连续追问默认拆为独立问答对，但生成的问题必须写清**提问背景**，如"（承接上一题关于项目A的追问）当时为什么选这个方案？"
- 输出严格 markdown：每题标题 + "问：" + "答："，带序号、话题标签、追问关系标注（`parent_id`）。

### FR4 切分
- 切分为 `{id, parent_id, topic, question, answer}`；校验条目数与 markdown 一致、追问关系正确；空答/超长答标记。

### FR5 逐题分析（批量）
- 输入：`ResumeSummary` + 单个问答对。
- 每题输出**四部分**：
  1. **问题考察点**（提问意图/考察能力）
  2. **原文回答**（清洗后原答）
  3. **原回答不妥之处**（遗漏点、逻辑问题、与简历不一致、表达冗余、缺量化等，引用原句定位）
  4. **AI 结合考察点、岗位、简历分析出的合理回答**（改进后示例）
- 约束：合理回答尽量基于简历内容拓展，引用简历经历/项目/量化成果；不编造简历外经历；无支撑时注明"简历中无直接支撑"；岗位从对话/简历推断，无法确定标"待确认"。
- 批量并发，失败重试，单题失败不影响整体。

### FR6 最终报告（markdown 文件）
- 输出 `interview_review.md`：顶部汇总（总题数、岗位、高频问题类型），逐题呈现上述四部分；支持下载。

### FR7 异常与边界
- 简历缺失/解析失败：允许仅基于对话分析，提示"无简历参照，改进回答受限"。
- 对话无有效问答：提示终止。
- 模型输出格式错误：重试/修复，仍失败降级展示原文。

## 4. 非功能需求
- 性能：20 题量级端到端 < 3 分钟，逐题并发。
- 隐私：不脱敏但传输加密、可配置不持久化。
- 可追溯：保留原始提取文本与中间 markdown。
- 可配置：提示词模板、忽略规则、输出字段。

## 5. 数据结构
```
ResumeSummary { basic, education, experiences[], projects[], skills[], highlights[] }
QAItem { id, parent_id, topic, question, answer }
Analysis { qa_id, assessment_point, original_answer, issues[], improved_answer, resume_refs[], position }
```

## 6. 验收标准
- 可复制文本的 pdf/docx 简历均能解析并生成结构化摘要；图片型被识别并提示；对话 docx 保留说话人前缀。
- `interview_qa.md` 问答完整、自我介绍与反问剔除、口语词明显减少、追问问题含背景说明。
- 切分条目数与 markdown 一致。
- 每题四部分齐全，不妥之处可引用定位，合理回答引用简历真实内容、不编造。
- 生成可下载的 `interview_review.md`。

## 7. 里程碑
M1 上传+解析+简历结构化摘要；M2 对话整理；M3 切分；M4 批量逐题分析；M5 报告生成与下载；M6 异常处理与提示词调优。

# 提示词模板

## 模板 A：简历结构化摘要（FR2）

```
你是简历解析助手。下面是一份简历的纯文本（可能来自 PDF 或 Word，含表格/多栏，顺序可能略乱）。请提取信息，仅输出 JSON，不要输出任何解释或 markdown 代码块标记。

要求：
1. 只提取文本中真实存在的信息，不得编造。
2. 量化成果（数字、比例、规模、时长等）尽量保留原值。
3. 无法确定的字段填 null 或空数组。

JSON 结构：
{
  "基本信息": {"姓名": null, "求职意向": null, "联系方式": null},
  "教育": [{"学校": "", "专业": "", "学历": "", "时间": ""}],
  "工作经历": [{"公司": "", "职位": "", "时间": "", "职责": "", "成果": ""}],
  "项目": [{"名称": "", "角色": "", "时间": "", "描述": "", "成果": ""}],
  "技能": [""],
  "量化成果": [""],
  "亮点": [""]
}

简历文本：
"""
{{resume_text}}
"""
```

## 模板 B：对话整理生成 interview_qa.md（FR3）

```
你是面试对话整理助手。下面是一份面试对话原始文本（来自 Word，可能含"面试官：/我："等说话人标记，也可能标记不全）。请整理为问答对 markdown。

任务与规则：
1. 识别说话人角色（面试官 / 候选人）。标记缺失时按上下文推断，无法确定则在问题后标注 [角色待确认]。
2. 按时间顺序提取"面试官提问—候选人回答"。
3. 忽略以下内容，不进入输出：
   - 自我介绍环节（候选人开场的自我介绍整段）。
   - 反问环节（"你有什么想问我的"及之后的全部内容）。
4. 口语清洗（最小必要原则）：
   - 去除语气词、口头禅、无意义重复与停顿（嗯、啊、那个、然后就是、就是说、对吧等）。
   - 保留事实、专业术语、关键数据、原句结构与原意，不得改写事实或增删信息。
5. 追问处理：连续追问拆为独立问答对；但问题中必须写清提问背景，格式如：
   "（承接上一题关于【项目A】的追问）当时为什么选择这个技术方案？"
6. 输出严格 markdown，每题格式：
   ## Q{序号}｜话题：{话题标签}
   - 追问自：Q{父序号}（无则省略此行）
   **问：** {清洗后问题}
   **答：** {清洗后回答}

只输出 markdown，不要额外解释。

对话原文：
"""
{{dialogue_text}}
"""
```

## 模板 C：逐题分析（FR5，供参考）

```
你是面试复盘分析助手。请基于【简历摘要】与【单个问答对】分析这道面试题。

【简历摘要】
{{resume_summary_json}}

【目标岗位】
{{position}}（无法确定则写"待确认"）

【问答对】
问题：{{question}}
原文回答：{{answer}}

请输出以下四部分（markdown）：
### 1. 问题考察点
说明面试官想考察的能力/动机/一致性等。

### 2. 原文回答
原样保留清洗后的回答。

### 3. 原回答不妥之处
逐条列出：问题类型（遗漏/逻辑/与简历不一致/冗余/缺量化等）+ 引用原句定位 + 简短说明。

### 4. 合理回答（改进示例）
结合考察点、岗位与简历内容给出改进后的回答；若简历中的经历/项目/量化成果对回答有用，则需参考，若对于问题回答需要的内容，简历中不涉及，则需要适当编造。
```
